Historical assessment. See [current outcomes and remaining platform limits](FULL_AUDIT.md) and [implementation tracker](AUDIT_IMPLEMENTATION.md) for the status of these findings after implementation.

Scope: Python sidecar, Rust ASR actor/IPC/native adapter, rewrite prompts/client/server/safety gate, context state, and their callers/tests. Existing uncommitted CUDA-graph, precision, context-sizing, and deadline changes were inspected and preserved. This report distinguishes code-confirmed defects from runtime risks needing live measurements.

## Confirmed remaining limitations / bugs

- **Native cancellation does not interrupt the request.** `src-tauri/src/asr/native.rs:200` uses blocking HTTP with a 180-second per-segment timeout; cancellation is checked before and after `.send()`, not while it is blocked. The cancellation closure only flips an atomic flag. Cancellation testing establishes flag delivery, but not prompt interruption of a real decode. Use an abortable async HTTP request and verify server inference stops when its connection is dropped.
- **Pipe writes can still block the actor indefinitely.** `src-tauri/src/asr/sidecar.rs:289` starts its reply deadline after synchronous stdin writes; `push_audio` also uses synchronous writes/flushes. A wedged reader with a full pipe can therefore block before the existing read timeout starts. Chunking bounds payload size, not wall-clock write duration. A bounded writer/transport supervisor needs a real stalled-reader regression.
- **The rewrite safety gate is a heuristic, not semantic preservation.** `src-tauri/src/rewrite/safety.rs:120` onward checks empty/meta output, an English negation/first-person subset, and word-edit distance. Changed numbers, dates, named entities, or multilingual negation can pass. Conversely, `tokenize` splits only on whitespace, so punctuation inside CJK text can turn a small edit into replacement of the entire single token and reject useful output. Add multilingual/number/entity fixtures before choosing stronger policy.
- **The optional live-partial path is unsafe to re-enable as written.** `LIVE_PARTIALS` is currently false. If enabled, `stop_stream` ignores `_wait_partial_idle(2.0)` failure and can run final inference while the partial worker still uses the same model and mutable graph cache. Model unload also does not synchronize with inference. Keep it disabled until inference ownership is unified.
- **Python capture is not bounded at ingestion.** The one-hour cap is applied in `stop_stream`, while binary frames and base64 frames append to `STATE.stream_audio` throughout capture. Prolonged external capture can grow RAM past the eventual transcription cap. Native capture already bounds retained samples. A bounded buffer must retain total-captured duration separately to preserve the existing honest truncation notice.
- **Context fitting is conservative and partly estimated.** `FlowClient` reserves 512 prefix tokens and measures only the transcript through `/tokenize`; long inputs can be rejected from a four-character/token estimate without asking the tokenizer. This intentionally preserves the original text, but wastes usable context on compressible input and cannot establish exact full-template token occupancy. Full rendered-prompt token accounting and paragraph-level refinement would improve long-form coverage. Requests are independent: no unbounded chat history accumulates.
- **ASR cap warning can be a false positive.** Python flags every output with `new_tokens >= max_new`, even when the final generated token is EOS exactly at that boundary. The warning should distinguish EOS termination from actual exhaustion.
- **GPU placement must match the probed device.** Python queries nvidia-smi device 0 and executes on `cuda`; llama-server is passed `--main-gpu 0`. The old capability choice of the most-free NVIDIA adapter could budget another adapter. Root is aligning admission to the actual default adapter; arbitrary adapter selection requires a device identity carried through probe, load, launch, cache keys, and telemetry. CUDA_VISIBLE_DEVICES can additionally remap CUDA's index and should be explicitly supported or excluded from assumptions.
- **GPU layer admission does not scale its scratch estimate with context size.** The current layer resolver budgets weights plus fixed overhead/reserve. Increasing `--ctx-size` increases cache/workspace requirements; launch fallback helps correctness, but choosing an excessive context may still trigger a slow CPU fallback. Calibrate context/cache memory as part of automatic placement.

## Throughput observations and measurement limits

- A local isolated 60-second waveform benchmark (five timed runs after priming) measured the frame-energy reduction at **9.011 ms / 29.290 MiB scratch before**, **1.682 ms / 0.156 MiB scratch after**: about 5.4x faster and 188x less peak scratch. This is preprocessing only, not an end-to-end ASR throughput claim.
- Existing working-tree changes prefer BF16 when it fits, fall back to INT8, capture a greedy CUDA decoder, use exact-length encoder padding, warm inference, and set physical-core CPU workers. Those are preserved. The best choice must be established per actual device/runtime/version; the comments' RTX 2050 timings are not universal guarantees.
- The static CUDA cache is capped at 1280; longer prompts safely fall back to `generate`. Per-token `int(tensor)` still synchronizes GPU to host, so graphs remove kernel-dispatch overhead but not all per-token synchronization.
- The ASR runtime segments long audio into at most 30 seconds; native ASR uses 8-second segments. Both process segments sequentially. A one-hour dictation can therefore have substantial post-release latency even with good real-time factor.
- The stable system/few-shot prefix and one llama slot permit reuse across styles; no conversation history is accumulated. Disabling reasoning prevents a tiny model spending the completion budget on hidden reasoning. These are valuable existing speed properties.
- `docs/asr-runtime-benchmark.json` contains English Python measurements, but native rows lack installed files and Hindi rows lack reference audio. It cannot prove that Python or native is globally fastest, nor establish multilingual quality. Benchmark realistic utterance lengths and technical vocabulary, report warm/cold runs separately, and pair ASR real-time factor with LLM input/output tokens per second and complete stop-to-text latency.

## Useful additions and removals

Add a hardware/runtime decision summary showing actual loaded model/device/precision, measured speed, fallback reason, and available memory; a long-dictation/context indicator with honest fallback or segment progress; and abortable cancellation with a visible terminating state. Use a fast preset that avoids refinement for raw/coding/already-clean text, and expose accuracy as a separate explicit preference.

Remove or isolate the disabled partial-inference implementation until it has one inference owner; keep mock engines test-only in production paths; consolidate preview and dictation intent/settings resolution (root is addressing their light-cleanup mismatch). Avoid duplicate heuristic caches with incompatible keys or a model selection UI that implies native has been benchmarked when it has not.

Changed in this audit: `model-runtime/qwen3_asr_runtime.py`, new `model-runtime/test_runtime.py`, `src-tauri/src/rewrite/client.rs`, `src-tauri/src/rewrite/server.rs`, and `src-tauri/src/asr/native.rs`. Passed: `python -m unittest discover -s model-runtime -p test_runtime.py -v` (4 regressions), `python model-runtime/qwen3_asr_runtime.py --selftest` (all existing checks), and `git diff --check`. Rust verification is handed to the root to avoid concurrent Cargo builds: `cargo test --lib rewrite::`, `cargo test --lib asr::native::`, then the normal backend suite. Actual ASR/LLM comparative throughput remains subject to serial live benchmarking; no blanket fastest-runtime claim is made here.
