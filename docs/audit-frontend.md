# Frontend and UX audit

Historical assessment. See [current outcomes and remaining platform limits](FULL_AUDIT.md) and [implementation tracker](AUDIT_IMPLEMENTATION.md) for the status of these findings after implementation.

Audit completed 1 October 2026. Scope: React bootstrap, event subscriptions, home dictation, onboarding, history, overlay/HUD, settings, shared controls, browser preview, TypeScript contracts, and frontend dependencies. This report distinguishes fixed defects from open findings and design recommendations. Desktop IPC, physical microphone capture, and operating-system injection cannot be established by a browser preview.

## Open findings

1. **P2 — History day filters operate on one page.** `HistoryView.tsx` fetches 50 rows, then applies Today/Yesterday/Earlier to those rows. Older matches can therefore be hidden behind an empty first page, and the header count is a page count rather than a total. Apply date/search filters in SQLite before pagination; return a total or next cursor; reset paging when a filter changes.
2. **P2 — Onboarding does not verify usable dictation.** `Onboarding.tsx` can finish when weights are merely installed, even if the runtime failed to load. Its microphone selection swallows `setAudioDevice` errors and saves independently. It also selects a model without explicitly leaving an automatic preset, so the eventual loaded model can differ. Finish after a short microphone/model smoke test, explain an automatic substitution, and await configuration changes.
3. **P2 — Status polling has coupled failures and overlapping work.** `useIntelligenceHub.ts` uses `Promise.all`, so one failure discards other healthy responses. A fixed two-second interval can overlap a slow refresh; all polling pauses during downloads even though other runtime status may change. Serialize refreshes, handle status results independently, and keep download events authoritative without freezing unrelated status.
4. **P2 — A displayed preference can differ from active execution.** Automatic presets may override saved device/model/precision and warmth preferences. The new current-plan panel exposes actual resident values, but some old controls still display saved preferences. Label the distinction and hide manual tuning behind Custom; show a pending reload state after a failed apply.
5. **P2 — Settings actions lack consistent pending states.** Some controls can be clicked again during a save, reload, or install. Preset changes trigger expensive model reloads; repeated clicks can queue competing requests and show a saved preset before its load succeeds. Disable dependent actions while applying, or coalesce to the latest selection; expose Applied/Loading/Failed explicitly.
6. **P2/P3 — Accessibility is partially verified.** Model runtime/backend selects and shared Field controls have accessible names, but settings `Row` labels are not universally connected to native inputs, custom widgets require individual review, and toast/live-region behavior needs a screen-reader pass. Preserve visible keyboard focus; do not announce every five-second hardware refresh when values are unchanged. Test zoom, reduced motion, contrast, keyboard-only use, and an actual screen reader.
7. **P3 — Technical settings dominate the first screen.** Five preset cards, model choices, compute/precision controls, downloads, and LLM controls compete. CustomControls and HardwareInspector also represent a second tuning vocabulary; repository search should decide which belong in the product and which are development-only. Keep one source of runtime truth and one place to choose writing behavior.
8. **P3 — Asset weight is disproportionate.** The production logo SVG is 288.68 kB (216.81 kB gzip), versus 112.56 kB gzip for the entire JS bundle in this build. Inspect the source asset and replace its embedded/oversized content with an appropriate optimized vector or raster before undertaking unrelated code splitting. This is a measured transfer-size issue; a desktop paint/load-time improvement has not yet been timed.

## UX changes with the highest value

- **Home:** one prominent recording control, shortcut hint, transcript, and a concise state: Ready → Listening → Transcribing → Polishing → Finished. Add a distinct insertion result and recovery action when paste fails. Keep prior text recoverable until a new session succeeds.
- **Settings:** organize around Speech, Writing, and Performance. Default Performance to Auto; reveal model/device/precision/offload settings when Custom is chosen. Keep dictionary, phone, appearance, and diagnostic details secondary. Avoid forcing the user to understand CUDA or GGUF to start dictating.
- **Readiness:** distinguish Downloading weights, Installing runtime, Loading model, Ready, CPU fallback, and Error. Give each failure one relevant recovery action. Prefer actual live model/device information over saved preferences.
- **Feedback:** show actual release-to-final time and ASR real-time factor after a dictation, with optional LLM prefill/decode detail. Use “Not measured” until a measurement exists. A generic loading spinner cannot explain long audio backlog.
- **History:** search/date filters should query the whole dataset, support export and original/cleaned comparison, and use honest totals. Preserve keyboard navigation and visible copy/error feedback.
- **Phone:** stable hold-to-talk placement with Connecting/Listening/Processing states, session-safe release/cancellation, transcript retention, and a visible desktop insertion result. Android lifecycle correctness must precede cosmetic changes.

## Verification

- `npm test`: **21 files, 82 tests passed**.
- `npm run build`: TypeScript and Vite production build passed.
- `npm run lint`: **0 errors, 6 warnings** for state-setting effects; these are recorded rather than described as a warning-free lint run.
- `npm audit`: **0 reported vulnerabilities** after compatible lockfile updates to affected transitive development packages.
- Browser checks: home/settings/model navigation, missing-model download action, disabled unsupported INT4, and preset controls inspected at narrow widths and a 1,024 px desktop breakpoint; no horizontal overflow at that breakpoint and no captured warning/error console entries. The browser accurately marks itself a preview. Native desktop dictation/injection and every OS/accessibility combination were not exercised.
