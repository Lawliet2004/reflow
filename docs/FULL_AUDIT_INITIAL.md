# Reflow full codebase audit and automatic runtime manager

Historical initial assessment, preserved for traceability. Later implementation supersedes the open-finding/status claims below. See [current outcome](FULL_AUDIT.md) and [implementation tracker](AUDIT_IMPLEMENTATION.md).

Completed 1 October 2026. This audit covers the Rust/Tauri desktop backend, Python ASR sidecar, native ASR adapter, LLM refinement and context management, React UI, Android companion, local/LAN API, persistence, injection, packaging, CI, and dependency scans. It preserves the substantial work already present in the working tree. The runtime manager and selected high-impact fixes are implemented; the open findings below remain work to do.

The fastest sensible default on this machine is the smallest installed speech model on CUDA, preferring BF16 when it fits, with a bounded refinement context and GPU offload admitted from remaining memory. Choose **Fast** for the lowest wait: it skips LLM refinement. Choose **Auto** to retain the selected writing behavior while adapting execution to hardware. No benchmark performed here establishes a globally fastest runtime across every model, language, device, or driver.

## Audit outcome

The highest-impact fixes remove an LLM circuit-breaker deadlock, serialize runtime process launches, detect dead ASR/LLM children, reject truncated LLM rewrites, fix callback-boundary resampling, correct Windows modifier-only hotkeys, close revoked WebSockets, preserve the current launcher until a replacement download verifies, make SQLite migrations transactional, and prevent incorrect/silent model-removal success. Python preprocessing uses much less temporary memory, reload admission no longer counts the incumbent model against its replacement, and transcript text is no longer written to the diagnostic log by the affected paths.

The UI now recovers from independent bootstrap/listener failures, reports several previously silent operation errors, correctly saves CUDA selection, blocks unsupported 0.6B INT4, offers speech-model download directly, associates shared field labels/errors, and exposes working runtime presets plus a current hardware plan. Changes to cleanup level now reach the actual refinement intent. Compatible dependency updates remove the reported npm vulnerabilities and the rustls vulnerability found during this audit.

Detailed evidence and file references are in [ASR/LLM findings](audit-asr-llm.md), [backend/Android findings](audit-backend.md), and [frontend/UX findings](audit-frontend.md).

## Automatic runtime system implemented

The execution policy is in `src-tauri/src/runtime.rs`. `get_runtime_plan` exposes the same policy to the frontend. Decisions affect a temporary settings copy; saved preferences are preserved. Custom passes the user's settings through unchanged.

| Decision                  | Behavior                                                                                                                                                                                                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ASR model                 | Auto/Fast use the smallest installed model. Accurate prefers a larger installed model that fits; Balanced follows the selected speech model within safe admission. CPU automatic fallback favors the smallest installed model.                                                                               |
| ASR placement / precision | Automatic presets resolve device and precision from hardware, live free memory, supported model formats, measured peaks, and measured ASR rate when competing configurations have observations. Unsupported Custom configurations return a structured failure. The sidecar also has its own launch fallback. |
| ASR + LLM memory          | Reserve projected ASR weights before planning refinement when ASR is not resident. Once loaded, use the live free-memory probe without subtracting the same weights twice. GGUF RAM admission uses quantized file size plus overhead, rather than an ASR FP32 estimate.                                      |
| LLM placement             | Automatic full or partial GPU offload leaves a reserve for ASR/desktop/workspace and falls back through the existing runtime launch path. CPU/partial offload uses physical-core thread sizing. The actual loaded backend/layers are displayed when resident.                                                |
| Context                   | Automatic contexts are bounded at 1,024 tokens on CPU/small GPUs, 2,048 at ≥8 GiB VRAM, and 4,096 at ≥16 GiB. Capacity tiers remain stable across transient free-memory changes, preventing unnecessary warm-server restarts. Custom context is preserved.                                                   |
| Residency                 | Keep ASR ready under automatic presets. Low available RAM disables warm refinement; insufficient RAM suppresses an additional LLM load and retains deterministic cleanup. Only the target already-loaded refinement model bypasses its additional admission estimate.                                        |
| Speed mode                | Fast bypasses LLM refinement without erasing the user's saved writing tier. Selecting a writing level that requests refinement exits Fast.                                                                                                                                                                   |
| Timing of changes         | Re-evaluate at model-load/refinement-launch boundaries. Recording is protected against model reload. Startup waits for ASR to settle before planning refinement. Runtime lifecycle operations are serialized.                                                                                                |
| Observations              | Record actual ASR device/precision and real dictation RTF. Persist observations by hardware fingerprint, with a serialized merge and temporary-file promotion. Keep worst observed memory/load peaks and latest rate values.                                                                                 |
| User control              | Auto/Fast/Balanced/Accurate/Custom appear in Model settings. Manual ASR/runtime placement changes select Custom. A current-plan summary explains selection and fallback.                                                                                                                                     |

The policy retains the selected Python/native ASR family. It does not download or switch families just because one is estimated to be faster. Native weights were absent here, so an accuracy-qualified Python/native comparison was unavailable. It also does not yet run an exhaustive LLM offload/thread/context search, track thermal/battery conditions, or continuously migrate live allocations when another app claims memory. Those are concrete extensions, not capabilities to imply in the UI.

GPU admission now uses the default NVIDIA device that the loader targets, rather than budgeting whichever NVIDIA adapter has the most free memory. `llama-server` uses main GPU 0 with split mode disabled. Arbitrary multi-GPU selection, CUDA_VISIBLE_DEVICES remapping, and Vulkan adapter identity across mixed vendors still require a consistent device identity throughout probe/load/launch/cache/telemetry.

### Context management findings

Refinement requests are independent; no unbounded conversation history is accumulated. Stable prompts and the warm server permit prefix reuse. Completion limits and conservative input/output reservations bound requests. Token-limit completion now preserves the complete deterministic transcript instead of accepting a partial rewrite.

Remaining gaps: the client tokenizes the transcript, not the entire rendered chat template, uses a fixed prefix reserve, and can reject very long input from an estimate. Oversized text safely falls back, but there is no complete paragraph-level LLM refinement implementation. Layer admission uses fixed workspace overhead rather than a measured context-dependent cache budget. The configured rewrite timeout behaves as a floor with token-dependent scaling, so its “give up after” wording needs correction. See the ASR/LLM report for precise triggers.

## Measured runtime on this hardware

Hardware observed: **NVIDIA RTX 2050, 4,096 MiB**, driver 592.82; **AMD Ryzen 5 7535HS, 6 physical / 12 logical cores**. The installed llama-server flavor is Vulkan. Installed speech weights were Python 0.6B and 1.7B; native speech weights were absent.

[Machine-readable calibration](audit-runtime-benchmark.json) contains all runs. `scripts/benchmark_runtime.py` provides a reusable local, no-download calibration command using a corpus of audio paths and reference text.

| Experiment                                         | Median warm latency | Memory / rate                                    | Meaning                                                                       |
| -------------------------------------------------- | ------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------- |
| Python 0.6B, CUDA BF16, 10.54775 s English audio   | **766 ms**          | **RTF 0.0726**, ~1,850 MB runtime-reported VRAM  | About 13.8 audio seconds processed per compute second on this sample.         |
| Same ASR, INT8                                     | **1,250 ms**        | **RTF 0.1185**, ~1,314 MB runtime-reported VRAM  | Less memory, slower here; quantization is not automatically the speed winner. |
| Qwen3.5-0.8B Q4_K_M, CPU, 6 threads, 1,024 context | **328 ms**          | ~51 generated tokens/s on a warm repeated prompt | Isolated refinement benchmark, ASR unloaded.                                  |
| Same LLM, full GPU offload                         | **157 ms**          | ~106–114 generated tokens/s across runs          | Isolated refinement, roughly 2.1× lower median request latency here.          |

ASR had three repetitions per precision and WER 0 on **one short English reference sample**. This is not multilingual or representative quality evidence. LLM had three identical prompts per device; later runs benefited from prefix caching. They exclude audio capture, ASR residency contention, formatting, IPC, paste, and UI delay. GPU-only isolated latency must not be presented as the full application latency with both models loaded.

The BF16 initial load took 124.625 seconds including cold Python imports and concurrent validation load. INT8 reloaded in the same process in 6.64 seconds. Those are different startup conditions and are not a fair cold-load comparison. Separate cold-start benchmarking remains necessary.

An isolated 60-second waveform preprocessing experiment measured frame-energy calculation at 9.011 ms / 29.290 MiB peak scratch before and 1.682 ms / 0.156 MiB after. This is about 5.4× faster and 188× less scratch for that operation, not a 5.4× ASR improvement. A one-hour waveform previously implied about 1.84 GB of temporary arrays in this path.

## Valuable feature additions

1. **Microphone preflight and recovery.** Level/noise meter, endpoint identity, selected-device health, a short transcript test, and a clear reconnect path. This prevents failures before the user dictates something important.
2. **Hardware calibration with a quality gate.** Short representative utterances in the user's languages; compare installed ASR families/precisions and LLM CPU/full/partial GPU modes while both consumers contend. Store median/p95 latency, peak memory, and WER/CER or meaning-preservation score under exact hardware/runtime/model versions. Apply only stable gains outside recording. The implemented policy and calibration script provide a foundation; this complete wizard is not implemented.
3. **Real speed and backlog diagnostics.** Release-to-final, ASR RTF, first partial, LLM prefill/decode, paste delay, dropped audio, and warm/cold state. Prefer a compact home summary with details on demand.
4. **Long-dictation support.** Segment progress, bounded buffers, full-template context accounting, paragraph refinement, and explicit fallback notices. Never imply that an oversized transcript was completely refined when it was preserved instead.
5. **Recoverable writing.** Undo/paste recovery, history export, original/cleaned comparison, nondestructive database recovery, and optional per-application style/dictionary profiles.
6. **Runtime repair and rollback.** Verified runtime inventory, active version/flavor, last successful smoke test, previous version, and one repair action.
7. **Reliable phone sessions.** Explicit connection/session states, resumable UI ownership, immediate revocation, bounded networking, and secure transport.

## UI and UX improvement plan

The home page should center on one dictation action and a recoverable transcript. Use one clear workflow: Ready → Listening → Transcribing → Polishing → Finished, with separate insertion success/failure. Show actual model/fallback information compactly; keep detailed tuning in settings.

Group settings into Speech, Writing, and Performance, with Auto as the default. Put manual model/device/precision/context/offload controls behind Custom. Downloads and runtime repair should form a single readiness checklist with concrete states and retry actions. A model file on disk is not the same as a running model.

For history, query the whole dataset before filtering/paging, show honest totals, preserve raw/cleaned text, and add export. For phone, prioritize lifecycle-safe hold/release and clear processing state before visual polish. Across desktop/mobile, keep visible keyboard focus, connected labels, actionable errors, predictable pending states, readable contrast, and reduced-motion support. Verify with keyboard, zoom, screen reader, narrow windows, and real native recording.
