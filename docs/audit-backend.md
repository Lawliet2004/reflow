# Backend and Android audit

Historical assessment. See [current outcomes and remaining platform limits](FULL_AUDIT.md) and [implementation tracker](AUDIT_IMPLEMENTATION.md) for the status of these findings after implementation.

Audit date: 30 September 2026. This covers desktop capture/resampling/VAD, LAN HTTP/WebSocket API, pairing, SQLite history, keyboard hooks, clipboard injection, model management, runtime installation, packaging, and the Android companion. ASR inference, LLM inference, context budgeting, hardware profile selection, desktop UI, and session orchestration are covered by the other audit sections.

Severity: P1 means a core workflow can fail, a session can escape its lifecycle, or an access boundary is ineffective. P2 means a reproducible reliability or usability defect. P3 means a lower-impact limitation or cleanup opportunity. Findings marked "open" remain in the application; a static audit is not a promise that all hardware and platform combinations were exercised.

## Open issues ordered by impact

### P1: Android hold gesture and recording lifecycle

`android/app/src/main/java/com/reflow/android/ui/ReflowApp.kt:254` uses `pointerInput(listening)`. `startSession()` sets `listening = true` while the press coroutine waits for release. Changing this key restarts the pointer handler, and the code has no `try/finally` around `tryAwaitRelease()` at lines 257-259. The release-to-stop workflow can therefore be canceled while the recorder keeps running. The Compose [gesture documentation](https://developer.android.com/develop/ui/compose/touch-input/pointer-input/understand-gestures) explains that changing a pointer-input key restarts its handler.

The screen has no disposal cleanup. Navigating to History/Settings, rotating, or leaving the composition can lose the recorder/socket references while their work survives. `onFinal` stops the recorder/service but never closes the socket. `onError`, `onPartial`, and `onFinal` arrive on OkHttp callback threads and directly mutate UI-owned state and stop resources. A new press during processing can race the old socket's callbacks against the new recorder/socket references.

Recommended correction: an explicit Idle/Connecting/Listening/Processing/Error state machine owned by a ViewModel/service; a stable gesture key; a `finally` release/cancellation path; coroutine dispatch to the main thread for UI state; session identity checks for callbacks; and disposal/final/error socket closure. Test hold/release, permission denial, press during processing, screen navigation, rotation, network loss, and desktop model failure on API 26 and API 35 devices. These Kotlin changes were not made without an Android build/device verification path.

### P1: Android recorder start/stop race and hardware errors

`android/.../audio/PcmRecorder.kt:20-52` does not check `getMinBufferSize()` error codes or `AudioRecord.state`; `startRecording()` exceptions escape the UI event handler. Negative `read()` results cause a busy loop instead of reporting a device failure. Stop releases `AudioRecord` while its worker may still be reading or delivering a frame, then drops the thread reference without joining. If the same recorder is restarted before the old thread observes `running = false`, that thread can continue against a released recorder.

Use a session-specific stop flag, validate initialization/recording state, stop then join the worker before releasing, handle read errors, and surface an actionable microphone error. The foreground `DictationService` only displays a notification; the recorder is still owned by the screen. `START_STICKY` (`DictationService.kt:36`) can restart a "Listening" notification without a corresponding recording. Move actual ownership into the service or remove its restart behavior.

### P1/P2: Runtime replacement is not transactional

`rewrite/runtime_install.rs:742-807` extracts files directly into the shared `bin` directory. A full disk, filesystem error, interrupted process, or a concurrent runtime launch can still leave a mixed installation. Stopping both consumers before extraction fixes ordinary Windows file locks, but no lock spans extraction and a new `ensure()` launch. Existing CPU/Vulkan DLLs are not removed when changing flavors. Runtime identity records only a label in `llama-server.kind`; it does not record pin, architecture, dependency inventory, or verified executable digest (`runtime_install.rs:132-153,520`).

Stage and verify the full payload in a separate version/flavor directory; launch-smoke-test it; coordinate native ASR and LLM transitions; then atomically switch the active runtime pointer. Keep the previous complete version for rollback. This is a better foundation for automatic hardware tuning than repeatedly overwriting one shared installation. Unix tar extraction also skips symlinks; test the actual Linux/macOS pinned archives and dynamic loader resolution before claiming support.

### P2: Microphone selection can reject a working device

`audio/capture.rs:33-120` treats name substrings as capability evidence. A system whose only input is a functional Bluetooth headset or deliberately selected virtual microphone can receive "No usable microphone" because its name has a negative score. An explicitly stored device name that disappears silently selects a different device. Displayed device IDs are names, so duplicate endpoint names are ambiguous.

Prefer the user's explicit selection, validate actual samples/stream health, and offer a microphone test with device identity and level feedback. Heuristics can rank suggestions without hard-disabling working endpoints. Use stable endpoint identifiers where supported and report a missing selected microphone before automatically switching.

### P2: Desktop capture failure is only logged, and overload loses audio

`audio/capture.rs:239-244` sets recording state before stream creation/play succeeds, and the stream-error callback only logs. Device unplug/backend failure can leave the product displaying a recording with no usable audio. `capture.rs:404-410` drops chunks when the sample channel is full and reports it only in logs. This keeps memory bounded but can silently damage the transcript exactly when inference is too slow.

Propagate capture failure to session state, reset the recording flag on every start failure, count dropped samples, and expose "microphone disconnected" or "audio backlog" as a recoverable condition. Feed drop counts/backlog into the automatic settings controller. Keep allocations, blocking locks, and repeated warnings off the real-time capture callback.

### P2: Clipboard restore covers only text

`injection/injector.rs:82-89,139-168` snapshots `clipboard.get_text()` only. If the user copied an image or other nontext clipboard format, successful dictation replaces it and the restore option does not restore the original content. Multiple closely spaced injections can also snapshot the previous injection's temporary text rather than the original user clipboard. The generation check correctly protects a later explicit user copy; this part is useful and should remain.

Preserve supported clipboard formats or state clearly that restore covers text. Retain the original clipboard snapshot across a chain of pending injections. Foreground equality proves which window received a chord, not whether its text field accepted the paste; keep the transcript recoverable and avoid claiming acceptance as verified.

### P2: LAN binding changes do not close the old server's upgraded sockets

`api/server.rs:95-128` uses graceful shutdown for listener changes, but upgraded WebSockets are independent. This audit closes them for device revocation and API disable. Switching from LAN to localhost while keeping API enabled can still leave a connection from the old LAN listener alive. Associate each connection with its server generation/shutdown signal and cancel it when that listener stops. Serializing `sync_server()` would also avoid concurrent settings updates racing stop/start and bind.

### P2: Blocking platform work runs in async LAN handlers

`api/server.rs:292-318` calls clipboard/focus/paste routines containing sleeps and a global synchronous mutex directly in a Tokio HTTP handler. History handlers perform synchronous SQLite work in the same runtime. Bursts from paired clients can occupy async workers and delay stream processing. Move platform injection/database work to bounded blocking jobs; serialize injection with a bounded queue; cap text payloads and reject new work when overloaded.

### P2: Android network operations can remain pending indefinitely

`android/.../net/ReflowClient.kt:19-21` uses `readTimeout(0)` for all HTTP calls, so pairing/history/injection can hang indefinitely after a connection succeeds. Compose coroutine cancellation does not cancel the underlying synchronous OkHttp Call. WebSocket sends ignore `send()` failures (`ReflowClient.kt:145,149`), with no ping timeout or explicit backpressure/error handling. `openStream()` does not apply the LAN-host validation used by pairing and REST methods; stored connection ports are not range-validated. `isAllowedLanHost()` resolves DNS separately from the actual connection, so it is not an enforcement boundary against rebinding.

Use bounded HTTP timeouts, cancellable calls, a separate WebSocket client with heartbeat/connection state, and send-failure/backlog handling. Prefer validated literal private IPs or bind validated DNS results to the connection. IPv6 localhost is allowed by validation but interpolated into URLs without brackets. Protecting pairing/history/audio confidentiality requires authenticated encryption, since the current bearer-token LAN protocol intentionally uses cleartext HTTP/WebSocket. This is an existing transport limitation, not an internet-facing API deployment claim.

### P2/P3: History recovery and search efficiency

`AppContext::bootstrap()` still panics when opening/migrating SQLite fails. Provide a recovery screen that preserves the existing database and offers retry/export rather than destroying history. `history/db.rs:124` builds an index on `final_transcript`, but the `%query%` search pattern scans across multiple transcript/application columns; this index does not provide ordinary substring-search acceleration. Consider SQLite FTS for large histories, or remove the unused text index after measuring. Percent/underscore in user search act as LIKE wildcards; escape them if the intended behavior is literal search. Pagination casts arbitrarily large offsets to signed integers; cap them. `clear_today()` has a UTC-midnight fallback for ambiguous/nonexistent local midnight; timezone-transition tests are still absent.

### P2/P3: Packaging commands and supported platforms

`scripts/package_windows.ps1:68` and `scripts/package_linux.sh:54` run `cargo build --release`, which produces a binary rather than the installers claimed by their comments/completion messages. `-SignBinaries` (`package_windows.ps1:75-79`) prints a signing message but only contains a commented signtool example. Both scripts still require Python even for a native-ASR deployment. Windows frontend build runs before the script changes to the repository directory, so invocation from another working directory can fail or run a different package's build.

Use one actual Tauri bundle command from a verified project root; make signing either functional or explicitly unavailable; restore the caller's working directory. `scripts/kill-running.cjs:14` uses `pkill -f reflow`, which can terminate unrelated processes whose command lines contain that substring. Use the exact executable identity/PID and a graceful shutdown request where possible. Release CI publishes macOS installers, while `platform/macos.rs:16` has no text injection, active-window implementation, or startup integration; default modifier-only shortcuts also rely on a Windows-only hook. CI has no macOS test job and no Android job. Expose these support limits and add platform gates before promising parity.

## Additions worth prioritizing

1. A microphone preflight: selected device, live level, noise level, missing-device recovery, and a short transcript test. This removes device-name guessing from the user's critical path.
2. An end-to-end speed panel showing ASR real-time factor, time to first partial, release-to-final, LLM prefill/decode throughput, paste delay, backlog, and dropped samples. Optimizing tokens/second alone cannot diagnose missing audio or a 350 ms double-tap delay.
3. A runtime inventory showing active executable pin/flavor, verified model files, last successful smoke test, previous recoverable version, and one repair action.
4. Phone connection states with a clear distinction between connecting, listening, desktop processing, and unavailable. Close completed sockets, retain the transcript, and show paste fallback instead of ignoring the injection response.
5. History export and a nondestructive recovery route, plus a literal/FTS search mode when history size warrants it.
6. For LAN use, encrypted pairing with a pinned desktop identity, explicit per-device permissions, and immediate active-session revocation.

## Remove or simplify

- Remove `api_mdns` from settings until discovery exists; repository search found only the field/default/type declarations, with no mDNS implementation.
- Remove the Android CAMERA permission until an in-app scanner exists.
- Remove the unused VAD pre-roll buffer/drain path if capture keeps sending every sample. `drain_pre_roll()` has no caller; maintaining it does not protect speech onset in the current pipeline.
- Remove or implement the packaging scripts' unused signing switch and misleading installer completion messages; consolidate packaging around the real release bundle path.
- Replace repeated hardcoded negative microphone-name rules with a ranked recommendation and actual stream test.
- Avoid shipping macOS as an equivalent dictation platform until its hotkey/injection workflow is implemented and tested; alternatively describe clipboard-only behavior accurately.
