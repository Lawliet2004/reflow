# Audit implementation and verification

22 October 2026. Follow-up to [the original audit](AUDIT.md). Existing uncommitted work was preserved. Tests use disposable application directories; the user's installed models, settings, history and Python environment were not changed. Existing Python was used only to execute model-free tests. Nothing was published or pushed.

The original findings and evidence remain historical observations. The updated [67-scenario matrix and acceptance procedures](SCENARIOS.md) describe the current implementation. “Implemented with acceptance pending” means code and deterministic coverage are present but physical customer acceptance is still required.

## Operational limits and acceptance

Use [the acceptance procedures](SCENARIOS.md) before broad distribution. No Windows, macOS, Android, microphone, external insertion, legacy GPU, ARM or performance acceptance was performed here.

Cancellation is checked during extraction between archive entries, download/body/hash chunks and inference/decode boundaries. A synchronous archive/hash operation or blocked transport read may delay response; native model HTTP requests have a 30-second bound and retry from preserved partial bytes, while SDK read waits can last until their configured timeout. Cancel is scoped to the active model, with a fresh per-installer ownership flag; it is not a general cancel-all command. Completed package cache entries survive repair; killed partial pip wheel transfers are not promised to resume across processes.

Old verified Python generations are deliberately retained after promotion, consuming storage; Remove managed environment removes them under the lifecycle lock. Runtime readiness is per selected engine/device; switching profiles may require setup for that profile. Explicit interpreter overrides require their owner's repair. Retained audio uses an additive schema version 7 with encrypted chunk fields and cascading retention deletion; old binaries cannot open the newer schema. Back up application data before a user-directed downgrade.

Wheel locks are resolved for CPython 3.12 on supported target triples. This does not claim MPS/AMD acceleration, Windows ARM, musl, generic Jetson support or every distro GUI ABI. Unknown or incompatible combinations should remain blocked or use the supported CPU/lightweight path.

The release workflow still automatically publishes a complete release on a matching tag. Whether macOS preview artifacts should instead be distributed separately is a product decision for a future policy change; this task did not change it.
