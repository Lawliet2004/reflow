# Backend audit and release verification: 0.4.0

Audit date: 7 October 2026. The release candidate includes the existing local changes and five commits ahead of the previous main branch; those changes were preserved.

## Scope

Reviewed Rust recording/session ownership, audio drains, model loading and cancellation, runtime downloads and activation, SQLite history/encryption/retention, settings recovery, dictionary learning, imports/transfers, local API permissions and TLS pairing, model-output handling, native platform adapters, Python speech runtimes, installer tooling, and CI/release workflows. Independent adversarial reviews covered storage/privacy, inference/runtime lifecycles, and release/session boundaries.

## Verification

An additional cleanup failure came from comparing a correct phrase-restart edit against both copies in the raw source. The gate now uses the existing conservative duplicate cleaner for a source-only comparison, after proving that removed words were exact adjacent copies of 2–6-word phrases. Meaningful repetition, quotes, completed clauses and all raw-source meaning safeguards remain protected. Deterministic tests cover both accepted restarts and rejected changes to names, quantities, intent and roles.

Local verification on Windows:

- Rust: `cargo test --locked -j 2 --manifest-path src-tauri/Cargo.toml --lib --tests --no-fail-fast` passed 790 tests across 41 targets, with five opt-in tests ignored by the default suite.
- Four additional opt-in Rust tests passed: installed-model dictation and writing corpora, Phonon transcription on both CPU and CUDA, and native Windows text-field observation. The native test recognizes edits and excludes password and read-only controls.
- Frontend: `npm run check` passed lint, formatting, types and 224 tests across 42 files. The production build passed.
- Python: sidecar selftests, 32 model-free runtime regressions, nine calibration/helper tests and three finite-timeout protocol tests passed. The real Zipformer protocol fixture passed streaming, finalization, silence, repeated stop, cancellation/restart and English-only checks.
- Packaging and release tooling: all 16 tests passed, including truncated, missing, unexpected, old-version and tampered assets, and missing or mismatched build manifests.
- Rust formatting and Clippy with `-D warnings` passed. `npm audit` reported zero vulnerabilities; the Cargo audit default gate passed with the informational warnings described below.

The installed Qwen 1.7B CUDA model loaded and warmed successfully. Phonon CPU and CUDA each reproduced the labelled English sentence exactly. Writing probes met 12 of 15 quality criteria and preserved safety on all 15; automatic paragraph/run-on handling and an irregular-verb edit did not meet their quality criteria. These are explicit quality limits, not a claim that every model output is correct. Rejected unsafe or uncertain edits preserve the complete prepared original.

Remote validation is recorded in [CI runs](https://github.com/Lawliet2004/reflow/actions/workflows/ci.yml) and the [0.4.0 release run](https://github.com/Lawliet2004/reflow/actions/workflows/release.yml?query=branch%3Av0.4.0). The workflow requires the complete reusable CI suite before preparing a draft, then all platform builds, native launcher smoke checks, Android signature verification and exact installer size/hash matching before publication. A published [0.4.0 release](https://github.com/Lawliet2004/reflow/releases/tag/v0.4.0) is evidence that those publication gates completed; consult the run logs for the individual platform results.

The Python sidecar's asynchronous model loader also had no overall load deadline. Status polling now retires a loader after 15 minutes and reports a timeout with reload guidance. Protocol regressions cover responsive and mute loaders, retry, successful resolution and exclusion of active downloads. A process last known to be downloading that subsequently becomes permanently mute remains protected; without a trustworthy completion signal, this deadline cannot distinguish it from a legitimate long download.

Windows socket fixtures now explicitly make accepted sockets blocking. A delayed-client regression reproduces the previous immediate connection abort. The CUDA capability regression runs in a separate test process so parallel sidecar status updates cannot overwrite its global fixture state.

Writing checks require actual model application on each safe minimal-edit case, and exact original fallback with a specific safety-rejection error for rejected paraphrases. A deterministic HTTP regression covers “I need the key to open the door” as a rewrite of “i need the key, for opening the door”. The current lexical and scoped-preposition guards deliberately retain the original for this candidate; they do not claim to recognize every equivalent grammatical paraphrase. Natural repeated-phrase cleanup remains a mandatory live check.

## Limits

macOS is a clipboard preview with ad-hoc signing and no notarization; native insertion and active-window/startup parity remain unavailable. Physical-device dictation and permissions cannot be certified for every platform or hardware class by hosted CI. Local live-model tests use the installed development-machine runtimes. Model-free CI covers protocol/cancellation/error handling without downloading all model weights.

Cargo audit found no vulnerability advisories that fail its default gate. Informational transitive warnings remain for proc-macro-error, the unic crates, [glib VariantStrIter unsoundness](https://rustsec.org/advisories/RUSTSEC-2024-0429.html), and a yanked chacha20 version. The glib iterator is not called directly by application code; these dependencies are part of upstream desktop/keyring dependency trees and should be revisited with upstream upgrades. This does not establish that every transitive code path is safe.

Installer inventory and basic format/truncation checks do not independently prove full container integrity, installability or embedded architecture/version. Publication compares each downloaded installer's exact size and SHA-256 with its platform build manifest, tying those bytes to the corresponding build output. The checksums and manifests are release-workflow evidence, not independent cryptographic attestation of source provenance. The launcher smoke proves process startup and dynamic loading, while physical dictation and desktop integration require device testing. Crash cleanup skips ambiguous paths, live parents, and non-PID-1 subreapers rather than claiming universal orphan detection.
